# 스펙·구조 정합성 점검

**기계적으로 판정되는 구조 위반**은 스크립트가, **문서를 읽어야 아는 스펙 불일치**는 직접 대조한다.

발견한 것을 **고치지 않는다.** 보고하고 어느 쪽을 고칠지 묻는다. `api-spec.md`·`erd.md`는 초안이라 코드 쪽이 맞는 경우가 실제로 있고, 스펙에 맞춘답시고 코드를 고치면 되돌리기 어려운 계약 변경이 된다.

## 0. 범위

엔드포인트 48개 중 구현된 건 일부다. 구현된 것만 대조하면 된다. 사용자가 범위를 안 줬으면 먼저 확인한다.

```bash
grep -rn "Mapping(" running-service/src/main/java --include="*Controller.java"
```

## 1. 구조 검사

```bash
python3 .claude/skills/spec-check/scripts/check_conventions.py .
```

레이어 의존 방향 / 에러 코드 3자 대조 / 미사용 예외 / 포트 규칙 / DTO 단위 접미사를 본다. 앞의 넷은 결정적 판정, 마지막은 휴리스틱이라 오탐이 섞인다.

스크립트가 못 보는 것 — 필요하면 직접 확인한다.

- 어댑터가 애그리거트를 반쪽만 복원해서 도메인 메서드가 죽은 코드가 됐는지
- 같은 일을 하는 포트가 이름만 다르게 중복됐는지
- JPA 엔티티 제약이 `erd.md` 표와 맞는지 (`nullable`·`length`·`precision`·`@Check`)

## 2. 스펙 대조

| 볼 것 | 코드 쪽 |
|---|---|
| 경로·HTTP 메서드 | `@RequestMapping` + `@PostMapping` 등 (`/api/v1`은 설정이 붙이므로 제외하고 비교) |
| 요청 필드명·필수 여부 | Request record + `@NotNull`/`@NotBlank` |
| 검증 메시지 문구 | Bean Validation `message` — **글자 단위로** 같아야 한다 (400 응답 본문) |
| 응답 필드명·타입 | Response record |
| 성공 상태 코드 | `ResponseEntity.status(...)` |
| 에러 코드·상태 | `ErrorCode` + `toStatus()` + `EXPOSED_CODES` |

ERD 대조는 JPA 엔티티와 본다 — 컬럼명·타입·nullable·UNIQUE·enum 값(`erd.md` §6).

## 3. 보고 전 — 의도적 변경인지 확인한다

**건너뛰면 같은 것을 매번 버그로 재보고하게 된다.**

```bash
git log --oneline -S "USER_NOT_FOUND" -- running-service/src
```

실제 사례: `USER_NOT_FOUND`는 `toStatus`가 401로 매핑하는데 `EXPOSED_CODES`에 없어 500으로 나간다. 명백한 누락 같지만 커밋 `d856b8f`(`🔨 Fix: USER_NOT_FOUND 500 에러로 수정`)가 **일부러 뺀 것**이다.

`-S`는 그 문자열이 추가·삭제된 커밋만 보여준다. 메시지가 애매하면 `git show <해시>`로 diff를 본다.

## 4. 보고 형식

```markdown
| 항목 | 스펙 | 코드 | 판단 |
|---|---|---|---|
| 온보딩 요청 필드 | `weightKg`/`heightCm` | `weight`/`height` | 스펙이 맞음 — 단위 접미사 규칙 |
| `USER_NOT_FOUND` | 케이스 없음 | 500으로 마스킹 | **의도됨**(`d856b8f`) — 조치 불필요 |
```

- 근거를 한 줄로 붙인다. 어느 쪽이 맞다고 하기 애매하면 그렇게 적는다.
- 의도된 것은 **조치 불필요로 명시**하고 목록에서 빼지 않는다. 다음에 또 발견했을 때 확인된 건임을 알 수 있어야 한다.
- 건수가 많으면 심각도로 나눈다: 런타임 동작이 스펙과 다른 것 → 내부 정리 순.

## 5. 마무리

**사용자가 고쳐달라고 하기 전에는 코드를 건드리지 않는다.** 수정이 여러 건이면 논리 단위로 나눌지 제안한다.

지금 안 고치기로 한 항목을 어딘가에 남겨둘지 확인한다. 대화가 끝나면 사라지는 발견은 다음번에 같은 비용을 다시 치른다.
